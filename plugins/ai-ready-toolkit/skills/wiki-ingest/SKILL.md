# Wiki Ingest

소스 하나를 위키에 녹여 넣는다. 목표는 "요약본을 하나 더 만드는 것"이 아니라
**기존 위키가 이 소스를 읽은 상태로 바뀌는 것**이다.

## 0. 대상 확인

사용자가 파일을 지정하지 않았으면 아직 ingest되지 않은 raw 파일을 찾는다:

```bash
ls raw/*.md
grep "^## \[" wiki/log.md | grep ingest
```

로그에 없는 파일이 후보다. **기본은 한 번에 한 건.** 여러 건이면 목록을 보여주고 순서를 확인받는다.

## 1. 읽고 맥락 잡기

1. `wiki/index.md` 를 읽어 위키에 이미 뭐가 있는지 파악한다.
2. `grep "^## \[" wiki/log.md | tail -5` 로 최근 흐름을 본다.
3. 소스 전문을 읽는다.
4. **주제가 아직 미정이면** (`CLAUDE.md`의 학습 주제가 비어 있으면) 여기서 사용자와 정하고 `CLAUDE.md`를 갱신한다.

## 2. 체크포인트 — 쓰기 전에 사용자와 맞춘다

작성을 시작하기 전에 짧게 보고한다:

- 핵심 주장 3~5개
- 위키에 **새로 생길** 페이지 후보
- 위키에 **갱신될** 기존 페이지
- 기존 위키와 **충돌하는** 지점
- 소스가 다루지만 주제 밖이라 버릴 부분

사용자가 강조점을 지시하면 그걸 따른다. 이 단계를 건너뛰지 않는다 —
어디에 방점을 찍을지는 사용자만 안다.

## 3. 소스 페이지 작성

`wiki/sources/YYYY-MM-DD-소스제목.md`

```markdown
---
type: source
title: 소스 제목
aliases: []
tags: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: ["raw/원본파일.md"]
confidence: high
---

# 소스 제목

**출처:** (원저자 / URL이 있으면 링크) · **ingest:** YYYY-MM-DD

## 핵심 주장

소스가 실제로 말한 것만. 문단으로 쓴다.

## 위키와의 연결

이 소스가 [[개념-A]]를 뒷받침하고, [[개념-B]]와는 이렇게 갈린다.

## 인용

> 원문 그대로 (영어면 영어로).

## 남은 질문

이 소스를 읽고 생긴, 아직 답 못 한 질문.
```

원문 요약이 아니라 **위키 관점에서 본 소스**를 쓴다. 원문이 필요하면 `raw/`를 보면 된다.

## 4. concept / entity 페이지 갱신

소스가 건드리는 모든 개념·대상에 대해:

- 페이지가 **있으면** → 새 내용을 통합하고 `updated:` 를 오늘로, `sources:` 에 이번 소스를 추가한다.
  기존 서술과 충돌하면 덮어쓰지 말고 `> ⚠️ **상충**` 블록으로 양쪽을 남긴다.
- 페이지가 **없고** 소스에서 실질적 내용이 나왔으면 → 새로 만든다.
- 이름만 스쳐 지나갔으면 → 페이지를 만들지 말고 `[[이름]]` 링크만 걸어둔다. (나중에 lint가 잡는다)

한 소스가 5~15개 페이지를 건드리는 게 정상이다. **역링크를 반드시 건다** —
새 개념 페이지를 만들었으면 관련된 기존 페이지에서도 그 페이지로 링크한다.

## 5. index.md 갱신

- 새 페이지를 해당 카테고리에 링크 + 한 줄 요약으로 추가
- Sources 표에 행 추가
- 소스에서 나온 미해결 질문을 "열린 질문"에 추가
- `updated:` 갱신

## 6. log.md 추가

파일 끝에 append. 기존 항목은 건드리지 않는다.

```markdown
## [YYYY-MM-DD] ingest | 소스 제목

핵심 내용 2~3줄. 신규: [[X]], [[Y]]. 갱신: [[Z]]. 상충: [[A]] vs 이 소스의 주장.
```

## 7. 보고

사용자에게 짧게: 만든 페이지, 갱신한 페이지, 표시한 상충, 새로 생긴 질문.
파일 목록을 나열하지 말고 **위키가 어떻게 달라졌는지**를 말한다.

## 규칙

- `raw/` 는 절대 수정하지 않는다.
- 소스에 없는 내용을 보태려면 `> 💭 **배경지식:**` 으로 표시한다.
- 소스가 주제와 무관하면 억지로 넣지 말고 사용자에게 말한다.
- 배치 요청("이거 다 처리해줘")을 받으면 2단계 체크포인트를 소스별이 아니라
  전체 계획 1회로 압축하고, 끝난 뒤 소스별 요약을 한꺼번에 보고한다.
