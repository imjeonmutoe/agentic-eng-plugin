# Wiki Lint

위키가 커질수록 조용히 썩는다. 주기적으로 점검한다.

## 점검 항목

### 1. 미해결 상충
```bash
grep -rn "⚠️" wiki/
```
각 상충에 대해: 새 소스로 해결됐는가? 조건 차이로 설명되는가? 여전히 미해결인가?
해결된 건 결론을 쓰고 표시를 내린다. **사용자 확인 없이 한쪽을 지우지 않는다.**

### 2. 고아 페이지 (인바운드 링크 0)
```bash
find wiki -mindepth 2 -name "*.md" | while read -r f; do
  n=$(basename "$f" .md)
  c=$(grep -rl "\[\[$n" wiki/ --exclude="$(basename "$f")" | wc -l)
  [ "$c" -eq 0 ] && echo "orphan: $f"
done
```
고아는 둘 중 하나다 — 링크를 걸어줘야 하거나, 애초에 위키에 속하지 않거나.

### 3. 실체 없는 링크 (stub)
`[[X]]` 로 참조되는데 `X.md` 가 없는 것. 참조 횟수가 많은 것부터 페이지를 만들 후보다.
```bash
grep -roh "\[\[[^]]*\]\]" wiki/ | sort | uniq -c | sort -rn
```
언급 3회 이상인데 페이지가 없으면 만들 값어치가 있다.

### 4. 오래된 주장
`updated:` 가 오래됐는데 그 뒤로 관련 소스가 여러 건 들어온 페이지. 갱신이 누락된 신호다.

### 5. 인덱스 동기화
`wiki/` 의 실제 파일 목록과 `index.md` 항목이 일치하는지. 빠진 페이지, 죽은 링크.

### 6. 지식 공백
`index.md` 의 "열린 질문"과 각 페이지의 "남은 질문"을 모아본다.
어떤 질문이 반복해서 나오는가? 그게 다음에 찾을 소스다.

## 출력

리포트를 먼저 보여준다. 심각도 순으로, 각 항목에 제안 조치를 붙인다.

```
## Lint 리포트 (YYYY-MM-DD) — 페이지 N개, 소스 M건

### 고쳐야 함
1. [[A]] vs [[B]] 상충 3주째 미해결 → 어느 쪽이 맞는지 판단할 소스 필요
2. index.md 에 [[C]] 누락

### 제안
3. "X" 가 5개 페이지에서 언급되는데 페이지 없음 → 만들까?
4. [[D]] 고아 페이지 → [[E]]에서 링크 걸면 자연스러움

### 다음에 읽을 것
5. 반복되는 열린 질문: "..." → 이런 소스를 찾아보면 좋겠다
```

**사용자 승인 후에 고친다.** 명백한 것(인덱스 누락, 깨진 링크, 빠진 역링크)은 바로 고쳐도 되지만,
페이지 삭제·병합·대규모 재구조화는 반드시 물어본다.

## log.md 추가

```markdown
## [YYYY-MM-DD] lint | 페이지 N개 점검

상충 X건(Y건 해결), 고아 Z개, stub 후보 W개. 조치: ...
```
