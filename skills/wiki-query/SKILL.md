# Wiki Query

축적된 위키로 답한다. 일반 지식으로 답하는 게 아니다.

## 1. 인덱스부터

```bash
cat wiki/index.md
```

인덱스에서 관련 페이지를 고른다. 인덱스만으로 부족하면 그때 grep:

```bash
grep -ril "키워드" wiki/
```

임베딩 검색은 필요 없다. 페이지 수백 개까지는 인덱스 + grep으로 충분하다.

## 2. 드릴다운

고른 페이지를 실제로 읽는다. 그 페이지의 `[[링크]]`를 따라 한 단계 더 들어간다.
**요약만 보고 답하지 않는다** — 인덱스의 한 줄 요약은 길잡이지 근거가 아니다.

## 3. 답변

- 근거마다 출처 페이지를 단다: `... ([[페이지명]])`
- **위키에 없으면 없다고 말한다.** 일반 지식으로 메우려면 `> 💭 **배경지식:**` 으로 명확히 구분한다.
- 상충하는 근거가 있으면 한쪽을 고르지 말고 양쪽과 조건 차이를 보여준다.
- 답변 형태는 질문에 맞춘다: 문단, 비교표, 타임라인, 목록.

## 4. 위키에 되돌려 넣기 (핵심)

**좋은 답은 채팅에서 사라지면 안 된다.** 아래 중 하나라도 해당하면 `wiki/synthesis/` 에 페이지로 남긴다:

- 여러 소스를 엮어야 나오는 답
- 비교·대조 (표로 정리한 것)
- 사용자가 "이거 좋다"고 반응한 분석
- 다시 물어볼 법한 질문

```markdown
---
type: synthesis
title: 질문 또는 주제
aliases: []
tags: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: ["[[근거-페이지-1]]", "[[근거-페이지-2]]"]
confidence: medium
---

# 제목

**질문:** 원래 질문

## 답

...

## 근거

어느 페이지에서 무엇이 나왔는지.

## 확실하지 않은 부분

```

만들었으면 `index.md`의 Synthesis 섹션에 추가하고, 근거가 된 페이지들에서 이 페이지로 역링크를 건다.

가벼운 질문(한 페이지 확인, 사실 조회)은 저장하지 않는다. 애매하면 사용자에게 한 줄로 묻는다.

## 5. log.md 추가

synthesis 페이지를 만들었거나 답이 위키 내용을 바꿨을 때만:

```markdown
## [YYYY-MM-DD] query | 질문 요약

답 한 줄. → [[synthesis-페이지]] 생성.
```

단순 조회는 로그에 남기지 않는다. 로그가 노이즈로 차면 쓸모가 없어진다.

## 규칙

- 위키 밖 웹 검색은 사용자가 요청했거나 위키에 명백한 공백이 있을 때만. 했으면 그 사실을 밝힌다.
- 답변에 쓴 페이지가 오래됐거나 `confidence: low` 면 그 점을 같이 말한다.
